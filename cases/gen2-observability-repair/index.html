Finding the failure behind a green dashboard

A runtime migration left alerts silently matching nothing. Positive controls exposed the incomplete fix.

By Vitor SchiavoUpdated October 2026~5 min read

The problem

After functions moved to a new runtime generation, the application dashboards still appeared healthy. But the log resource type and labels had changed, while alert policies and log-based metrics still filtered the previous format.

An audit identified 22 policies and two metrics in scope. Twenty-one policies were enabled, but the old filters could no longer match their intended events. An absence of alerts had become indistinguishable from an absence of incidents.

My contribution

I traced the migration's effect on resource labels and payload formats, audited related policies and metrics, applied the runtime-specific changes and validated the new filters against log messages known to exist. I also checked the application logging path where changing the filter alone would not restore visibility.

Why the obvious fix was incomplete

Replacing the resource type looked sufficient. It was not: some Go functions emitted structured JSON, while Python functions emitted plain text. A policy using a plain-text field could remain blind even after its resource filter was corrected.

Other policies used a search expression that already matched either payload format. Treating every filter as the same would have introduced unnecessary changes. I verified each shape instead of applying a universal replacement.

Results and measurement

The completion record confirms 22 policies and two metrics corrected and verified. A project-wide sweep found no remaining policy or metric using the obsolete resource filter.

The five-match comparison is a positive-control test for a specific known message. It demonstrates why the resource-only fix was insufficient; it is not a claim that every possible future failure was covered. Some signals were deliberately left disabled where they were redundant, rather than enabling everything indiscriminately.

What I learned

A filter returning zero rows is not a validation result until there is a known event it should match. Migration acceptance needs an observability check that exercises real payloads, not only a successful health endpoint.
